## 1. 서론

### 1.1 문서 목적 및 범위

본 문서의 목적은 소프트웨어학과 학부 프로젝트 과목의 성과물인 '스마트 미니 드라이브 제어 시스템(Mini Drive)'에 대한 종합적인 블랙박스 테스팅을 수행하고 그 정량적 결과를 기록하는 데에 있다.

본 문서에서는 스마트 미니 드라이브 시스템의 기능적 요구사항과 비기능적 성능 검증을 위한 테스트 기준, 범위, 상세 설계 케이스 및 최종 합격 유무를 명시한다.

### 1.2 프로젝트 개요

사용자가 웹 파일 탐색기와 모바일 앱을 통해 물리적 제약 없이 개인 파일을 보관, 업로드, 다운로드할 수 있는 경량형 클라우드 스토리지 '미니 드라이브'를 구축한다. 서버 스토리지 인프라를 기반으로 실시간 동기화 상태를 모니터링하고, 가용 용량 체크, 확장자별 자동 분류 및 보안 공유 링크 제어 기능을 종합적으로 통합 관리하는 효율적인 제어 시스템을 제공한다.

### 1.3 용어 정의

| 용어 | 설명 |
| --- | --- |
| 서버사이드 | 데이터베이스 관리, 파일 청크(Chunk) 조각 연산 및 다이렉트 오브젝트 스토리지 입출력을 담당하는 파일 서버 시스템 영역을 의미한다. |
| 클라이언트 | 사용자가 직접 조작하는 프론트엔드 인터페이스 영역으로, 웹 브라우저 기반의 대시보드와 안드로이드 전용 드라이브 앱을 포함한다. |

## 2. 테스트 개요

### 2.1 테스트 범위

본 테스트는 컴포넌트 내부 소스코드를 직접 검증하지 않고 인터페이스 외부 입력에 따른 출력을 확인하는 블랙박스 테스트 기법을 전제로 수행된다. 세부 테스트 범위는 다음과 같다.

| 범위 | 내용 |
| --- | --- |
| Web 기반 시스템 | Ⅰ. 웹 대시보드 내 Drag & Drop 파일 업로드 및 스트리밍 다운로드 정확성 확인<br>

<br>Ⅱ. 폴더 생성/트리 구조 변경 요구사항 충족 확인 |
| Android 기반 시스템 | I. 모바일 기기 내부 저장소 파일 업로드 및 동기화 동작 확인<br>

<br>II. 모바일 전용 압축 해제 및 파일 미리보기 요구사항 충족 확인 |
| Database | I. 웹/앱 간 실시간 파일 메타데이터(용량, 생성일, 확장자) 동기화 검증<br>

<br>Ⅱ. 사용자별 스토리지 쿼터(Quota) 제한 데이터 입출력 확인 |

### 2.1 테스트 항목 및 통과 기준

| 기능별 테스트 항목 | 통과 기준 |
| --- | --- |
| 회원가입 기능 | 유효한 이메일 도메인과 정책에 부합하는 암호 강도가 입력된 경우에만 임시 스토리지가 할당된다. |
| 로그인 기능 | 사전에 가입된 인증 정보와 일치할 때 드라이브 토큰 세션이 안전하게 수립된다. |
| 파일 공유 기능 (앱 한정) | 모바일 앱 내에서 고유 다운로드 URL 생성 및 접근 비밀번호/유효기간 정보가 서버에 반영된다. |
| 모니터링 기능 | 웹과 앱 화면에서 현재 사용 중인 전체 용량 정보가 오차 없이 동일한 실시간 데이터로 노출된다. |
| 입력 기능 | 파일 업로드, 폴더명 수정, 휴지통 이동 등 데이터 변경 조작이 웹/앱 인터페이스에 즉각 반영된다. |

| 비기능별 테스트 항목 | 통과 기준 |
| --- | --- |
| 브라우저 테스트 | 크롬, 사파리, 파이어폭스 등 독립적인 멀티 웹 브라우저 엔진 환경에서 드라이브 UI가 정상 구동한다. |
| 안드로이드 기기 테스트 | 다양한 API 레벨의 스마트 기기 및 해상도 환경에서 미니 드라이브 앱이 래그(Lag) 없이 정상 동작한다. |
| 보안 테스트 | 비인가 토큰 혹은 세션이 없는 사용자가 드라이브 내부 경로 파일 주소로 직접 우회 접근할 수 없다. |
